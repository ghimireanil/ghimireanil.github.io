Picking the Right Model Is Mostly About What You're Willing to Give Up

Tradeoffs in model size, latency, accuracy, and interpretability across NLP, Computer Vision, and Tabular Data

Introduction

Every model on a leaderboard looks great until you have to run it. Then the questions change: how big is it, how fast does it respond, and can you explain why it made a decision when someone asks. This piece walks through five pretrained models across NLP, computer vision, and tabular data, and what each one actually costs you in practice.

The models: GPT-3 and BERT for NLP, MobileNetV2 and EfficientNet-B0 for computer vision, and TabNet for tabular data.

Model-by-Model Breakdown

GPT-3: the API you rent, not the model you run

GPT-3's few-shot performance is still hard to match, but 175 billion parameters means 350GB of storage and 100-200ms cloud latency even before you account for cost. You're not self-hosting this. If your problem genuinely needs frontier generative capability – complex reasoning or open-ended writing – treat it as a managed API and budget accordingly. For anything narrower, it's overkill.

BERT: the workhorse for understanding tasks

At 110M parameters and 30.5ms inference, BERT sits in a comfortable middle ground. It scores 80.5% on GLUE, runs on enterprise hardware without drama, and its attention maps give you something to point to when someone asks why it flagged a document. For sentiment analysis, NER, or QA where you need real understanding but can't justify GPT-3's footprint, BERT is the default.

MobileNetV2 vs EfficientNet: speed versus accuracy on-device

MobileNetV2 is built for constraints. At 3.5M parameters and under 1ms on a flagship NPU, it's the obvious pick for real-time mobile object detection or edge camera analysis, where battery life and latency matter more than squeezing out another few points of accuracy. Its 71-72% Top-1 accuracy trails the field, but that's the tradeoff you're making on purpose.

EfficientNet-B0 sits a step up: 5.3M parameters for 77.1% Top-1, and the family scales up to B7's 84.4% if you have the compute. It's the better choice for cloud servers, robotics, or smart cameras where you can afford slightly more latency (~47ms on CPU) in exchange for meaningfully better accuracy.

TabNet: when you need to explain the prediction, not just make it

TabNet's pitch is interpretability built into the architecture – sequential attention masks that double as feature importance. This matters in healthcare or finance where someone will ask "why did the model flag this?" It can outperform XGBoost on multi-class problems (96.5% vs 93.9% in some comparisons) and scales from 81K to 660K parameters. The catch is training time, which can run an order of magnitude slower than tree-based models. If you don't need built-in explainability, XGBoost is still the faster path.

The Actual Decision: What Constraint Are You Optimizing For?

Cloud NLP Default

BERT – balance of size, speed, and interpretability. Use GPT-3 only if you need creative generation and can pay API costs.

Cloud Vision Default

EfficientNet-B0 – better accuracy at moderate latency. Scale to B7 if compute allows.

Edge / Real-time

MobileNetV2 – sub-ms latency, tiny footprint. Accuracy tradeoff acceptable for live applications.

Need Explainability

TabNet – built-in attention masks for feature importance. Use when downstream audits require justification.

Speed Over Everything

MobileNetV2 or quantized BERT – optimize for inference time first, accept accuracy loss.

Key Insight: None of this is about finding the "best" model. It's about knowing which constraint you're optimizing for. BERT and EfficientNet are safe defaults for cloud NLP and vision. MobileNetV2 wins when latency is non-negotiable. TabNet wins when someone downstream needs to see why. GPT-3 only makes sense when nothing smaller can do the job, and you're prepared to pay for it as a service.
